# 免费额度下的请求与查询优化

> 范围更新（2026-10-13）：卡牌参数、图鉴及历史对比已下线，archive/feed 采集已停止。下文涉及这些功能的数字与截图均为下线前验证记录；现行接口与操作以 README、deployment.md、data-contract.md 为准。

验证日期：2026-10-13。以下为本地 Worker、SQLite 查询计划和浏览器验证，不代表生产 Cloudflare 的计量结果。

## 已实施的变化

1. 卡牌字典等待 `/api/status` 确定来源和版本后再请求。`/api/cards/dictionary?stream=...&release=...` 一次返回展示元数据，不分页、不传输战斗参数；返回的 `stats` 为 `{}`，完整参数仍由卡牌列表和详情接口提供。
2. 浏览器按来源和不可变版本复用字典，合并同时进行的相同请求，最多保留四个版本。失败不缓存，允许下次重试。切换来源后旧结果不能覆盖当前字典。
3. `/api/status` 使用 60 秒 Cache API 缓存。无意义的 query string 不会拆分状态缓存；成功入库后立即删除当前机房的状态缓存，其他机房最多滞后 60 秒。缓存失败时正常回退 D1。
4. 卡组和卡牌搜索等待连续输入停止 300 ms 才请求；输入期间暂停旧条件请求，避免页码重置触发额外查询。清空搜索立即恢复，来源、卡牌、类型、稀有度和翻页操作仍立即响应。
5. 新增 `deck_cards(card_id,deck_id)` 关联表和来源类型索引。按卡牌筛选先读取匹配的关联记录，再用主键读取对应卡组；明确连接顺序，防止 SQLite 优先遍历 `deck_seen` 的全部卡组。来源类型筛选先按类型索引取去重后的卡组 ID。多出处仍只返回一套卡组。
6. 新增 `catalog_totals`，保存可见卡组总数。状态接口和无筛选卡组列表读取一行计数，不再全表 `COUNT(*)`。新增、隐藏、恢复、删除卡组时由事务内触发器维护计数；卡牌关联也由触发器随槽位变化更新。重复采集仅更新观察时间，不重复创建关联记录或增加总数。

## 本地结果

| 检查项 | 结果 |
| --- | --- |
| 默认首页实际 API 请求 | 4 次：卡组、状态、配卡目录、卡牌字典 |
| 字典请求 | 从两轮各 3 页改为一次请求 |
| 最新历史参数字典文档内容 | 1,088,738 → 48,233 UTF-8 字节（约减少 95.6%，未计 HTTP 压缩） |
| 已有 169 套卡组回填 | 1,352 条卡牌关联，计数仍为 169 |
| 本地数据库大小 | 4,259,840 → 4,538,368 字节，新增约 272 KiB |
| 1,000 套卡组、指定卡牌仅命中 10 套 | 查询计划从 JSON 逐套扫描改为卡牌索引及卡组主键查找 |
| 上述 COUNT 查询 SQLite VM 步数 | 44,728 → 125；这是本地执行指令数，不是 D1 `rows_read` |

普通 API 缓存命中后不会查询 D1，但仍会调用 Worker。不同搜索词和机房有不同缓存，不能假设全部命中。名称搜索仍保留子串匹配语义，没有声称普通 B-tree 能索引任意子串；这类请求主要通过防抖和缓存减少次数。

## 迁移与发布顺序

新增迁移：`migrations/0003_query_budget.sql`。它对已有槽位 JSON 做一次回填，不删除卡组或历史参数。已在本地现有数据库执行；新库迁移和已有数据回填均验证通过。

生产需要先应用数据库迁移，再发布 Worker：

```sh
npx wrangler d1 migrations apply royale-atlas --remote
npm run deploy
```

本轮没有执行生产迁移或部署。迁移的一次性回填也会产生 D1 读写和索引写入；当前 169 套卡组很小，未来已有大量卡组时应安排在当日额度有余量时执行。

验证命令：

```sh
npm run build
npm test
npm run test:integration
uv run --directory crawler --frozen pytest
```

查询回归测试使用 Python 标准库 SQLite，运行 `npm test` 时需有 `python3`（可通过 `PYTHON` 环境变量指定解释器）。现有 CI 同时配置了 Python/uv。

这些变化降低了日常消耗，不能承诺任意流量均在免费额度内。上线后应看 D1 `rows_read`/`rows_written`、Worker 请求和 CPU、`X-Atlas-Cache` 命中率；大量不同搜索或自动化流量仍可能用完额度。
