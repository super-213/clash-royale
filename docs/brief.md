# 我的主卡组更新简报

在卡组资料库点击爱心收藏，再点击「查看更新简报」或侧栏「主卡组简报」。旧的 `royale-saved` 浏览器收藏直接生效，无需迁移或登录。简报页的「管理收藏」进入收藏列表；展开卡组可以查看配置、出处或取消收藏。

也可以直接点击「自己配卡组」，无需先收藏公共卡组。编辑器使用两行四列、前三个特殊槽和下方/右侧卡牌收藏册。空槽点击卡牌直接填入并自动选择下一个空槽；满槽替换支持先选卡再点目标槽，或先点目标槽再选卡，没有额外的「使用／替换」确认。先选基础卡时栏位显示虚线提示，可以取消选卡；英雄牌选中或拖入后自动安排到合法栏位，不要求玩家自行调整。

电脑支持从收藏册拖入任意兼容槽位，以及卡组内部拖动交换；拖入时目标高亮，拖动结束不会再次触发点击放置。触摸操作关闭原生拖动，以点击为主。新增、替换、移除、换位和形态切换均支持一步撤销；选卡、搜索或失败操作不消耗撤销，撤销恢复八个槽位及原形态。撤销记录仅当前编辑会话保留，关闭/刷新后只恢复草稿本身。

支持中文/英文搜索、按类型筛选、按圣水/名称排序；卡组内已有卡牌置灰，禁止重复基础 ID。基础卡按目标栏位和目录能力自动激活觉醒或精英，普通栏位使用普通形态，英雄牌自动安排到精英或魔法栏位。魔法栏位的双形态卡可以切换觉醒和精英；没有接入个人账号的解锁状态，玩家应确认已解锁所选形态。

保存后立即以明确形态匹配公告。自配卡组可以编辑、改名、移除卡牌、删除和撤销删除；交换可拖动卡牌或点击「交换位置」再选目标槽。特殊形态移到普通栏位时还原为普通，英雄牌被移动到普通位置时自动重新安排。选择的槽位顺序保持不变，详情和导入基础链接采用同一顺序。

魔法栏位已有卡牌具有多种形态时，卡组下方直接显示「魔法栏位形态」切换按钮；同时支持觉醒与精英的卡牌可自由往返切换；普通形态由普通栏位决定。点击立即更新该槽位的卡图和形态，不需要移除、重选或点「替换」；草稿记住当前选择，保存后按所选形态匹配简报。

该入口经火枪手的觉醒 → 精英 → 觉醒 → 普通 → 精英往返及关闭/刷新恢复验证；375px 下入口与保存按钮可见，无横向溢出。33 项单元测试通过，其中覆盖目录中所有同时有觉醒和精英形态的卡牌，验证切换后保存身份与其他卡位不变、对应卡图以及简报形态匹配。

## 自配卡组与草稿

来源记录仅有普通形态时，使用中性卡位，不将前三张牌冒充特殊配置。列表、详情、简报和配卡编辑器的槽位均仅显示卡图与圣水费用，不再显示上下方的槽名、卡名或形态标签；卡名、形态与槽位说明仍保留在图片替代文本、辅助标签或悬停提示中。魔法栏位的形态切换按钮保留。「按当前槽位配卡」保留八张基础卡，以目录能力生成独立草稿，优先填充三个兼容的特殊槽，并尽量保留已记录形态；玩家确认已解锁情况后保存。它不是来源卡组实际使用形态的证据，来源记录和收藏身份不变。专属草稿键为 `royale-deck-draft:source:<source-id>`。

`data/card-form-images.json` 收录当前目录全部 61 个特殊形态的独立卡图，来自官方 API 素材链接和已核对存在的 RoyaleAPI 公开素材。它只补充显示素材，不从图片推断来源卡组形态。已保存的旧自配快照读取时补齐新素材；特殊卡图缺失或加载失败显示卡名占位，不回退普通卡图。

- `GET /api/deck-builder` 提供现有社区目录的 123 个基础 ID，以及 RoyaleAPI 网页形态目录中对应的能力。`data/card-names-zh.json` 从仓库 2023-10-18 的历史目录提取 120 个 ID 的中文名字，仅作名称翻译，未引入历史战斗参数。新卡没有可靠中文名称时保留英文。
- `shared/personal-decks.ts` 校验完整 8 张、不重复、身份已知、形态兼容。自配卡组具有独立 `local:<UUID>` 身份、明确槽序和 8 张卡牌的显示资料快照；改名/编辑保留 ID，不影响旧收藏。
- `royale-personal-decks-v1` 保存版本化的本地自配卡组，最多 10 套；`royale-deck-draft:new` 或 `royale-deck-draft:<local-id>` 保存各编辑草稿。关闭和 Esc 保留草稿，成功保存清除对应草稿。卡组读写经过校验；存储不可用时明确提示仅本次会话保留。
- 本地身份不会传给 `/api/decks?ids=…`、不会发布到公共 D1；公共收藏读取失败时，自配卡组简报仍可显示。全部功能无需登录，暂不支持跨设备同步。
- 个人明确槽序通过 `slot_order: explicit` 展示；来源组成仍按既有推导编排规则显示。个人所选形态只代表玩家选择，不证明实际解锁或游戏内生效。

## 首期范围

首期使用 `data/royaleapi-web/balance-2026-10.json`：2026-10-04 发布、2026-10-13 采集的第 88 赛季公告，共 17 组卡牌/形态调整、21 项数值变化。它是独立的公告数据，不是历史 release 差异，也不是完整的当前战斗参数库。原始数据的 `effective_at: null` 和 `live_version_verified: false` 保留并展示；未标明的等级不会被猜测为 11 级。

每组调整分别展示公告事实、编辑影响解读（推断）、建议观察（待实测）和章节原文。多个调整保留在同一组中，例如熔岩猎犬伤害提高与攻击次数下降、皇家幽灵生命值下降与伤害提高。原文百分比保留，不重新计算或从零基线生成无穷百分比。

## 匹配与读取

- `shared/brief.ts` 使用官方卡牌 ID 和槽位形态匹配，不依赖当前选中的卡牌资料来源或翻译名称。
- 同 ID、同形态为直接相关；觉醒/英雄专属调整不匹配已知普通形态。
- 卡组形态为 `unknown` 时，按同 ID 列为形态待确认，不计入直接相关。
- 普通形态调整遇到觉醒/英雄槽位时，列为「基础调整 · 继承待确认」。原始表格没有证明继承关系，因此不自动认定适用。
- 同张卡牌多项参数变化按卡牌计数，不生成整体强度分数。没有命中只表示本期未找到直接调整，未评估对手、环境或完整补丁覆盖。
- `GET /api/balance-briefs` 返回已收录期数、来源元数据和轻量卡牌身份目录（来自现有社区目录，含 ID、名称、图片、稀有度和圣水），不接收收藏、不需要 D1 迁移。轻量目录用于完整参数字典加载前的显示兜底和槽位编排，不参与强度判断。
- 收藏仍仅在当前浏览器中保存，沿用公开 `/api/decks?ids=…` 读取对应卡组。60 个收藏按 48/12 两批读取，未读取到的收藏单列提示，可重试或移除。读取失败不当作无调整。
- 图片加载失败显示卡名。空收藏、无公告、加载、请求失败、失效收藏均有对应状态。

## 新一期公告维护

1. 用现有网页导出流程保存新的公告 capture 与规范化 JSON，核对出处、发布日期、单位、形态和数值。不要用采集日期冒充发布或生效日期。
2. 在 `worker/balance-feed.ts` 增加新一期的构建数据，按发布日期从新到旧加入 `balanceEditions`，使用新的唯一 `id`。当前构建函数专门对应首期数据；新一期应显式接入自己的数据与解读，不复用旧解读冒充新分析。
3. 使用可信目录核对官方 ID。现有身份映射来自 `data/community.json`，中文名称参考历史卡牌目录；`Minion Giant` 保留原名，未猜测中文译名。
4. 为每组调整写可追溯的解读与观察项，明确混合调整。新指标和形态必须明确单位及匹配规则；不要推导未经数据支持的击杀线、胜率或总产水。
5. 运行 `npm run build`、`npm test`、`npm run test:integration`，检查收藏、形态、日期和手机布局，再按现有部署流程发布。页面会自动出现期数选择器（超过一期时）。

当前接口由应用代码打包提供，新增公告需构建部署；没有无人值守采集、推送通知、个人等级同步或推荐换卡功能。
